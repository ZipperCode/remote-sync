# 远端同步

用于 Obsidian 普通库文件和附件的轻量双向同步插件，支持 WebDAV 与 S3-compatible 远端。

## 范围

- 默认启用自动同步：文件新增、修改、删除或重命名后，等待 3 秒无新变化再同步。
- 保留 Ribbon、命令面板和设置页的手动同步入口。
- 支持 WebDAV、Amazon S3、Cloudflare R2 和通用 S3 兼容服务。
- 通过 Obsidian `requestUrl` 兼容桌面端和移动端。
- 可配置全局自定义请求头，每行 `Header-Name: value`，适用于 `User-Agent` 等服务端要求。
- 跳过 `.obsidian`、隐藏路径、临时文件和自定义忽略规则。
- 首次同步没有共同基线时，会要求选择首次同步策略，不会直接写入或删除文件。
- 默认使用"自动"策略：普通新增、修改和删除会自动同步；不可合并冲突（二进制、大文件或缺少基线）按修改时间较新的一侧自动处理。
- 文本文件双方都变化时会优先尝试三方自动合并；大文件、二进制文件或缺少基线导致无法合并时，默认按修改时间较新的一侧自动覆盖。
- 覆盖或删除前会写入本地 `.remote-sync-trash/<批次>/...`，并提供命令面板入口恢复备份。
- `mtime` 相同但大小不同的不可合并文件默认使用本地版本，覆盖前仍会备份旧版本。
- 支持从系统剪贴板粘贴外部文件到 Markdown 笔记和插件代码视图，附件位置使用 Obsidian 附件规则。

当前不包含端到端加密、multipart upload、服务端加密、ACL、对象版本管理和 Obsidian 配置同步。

## 远端配置

### WebDAV

填写 WebDAV 地址、用户名、密码和远程根目录。旧版本保存的 WebDAV 配置会自动按 WebDAV 远端读取。

### S3-compatible

设置页可选择：

- `Amazon S3`：默认 `region = us-east-1`，默认 `virtual-hosted` 地址风格。
- `Cloudflare R2`：默认 `region = auto`，默认 `path-style` 地址风格，Endpoint 形如 `https://<account-id>.r2.cloudflarestorage.com`。
- `S3 兼容服务`：默认 `path-style`，需服务端支持 SigV4 和 `ListObjectsV2`。

S3 配置包含 Endpoint、Region、Bucket、Prefix、Access Key ID、Secret Access Key、可选 Session Token 和地址风格。`Prefix` 只作为对象 key 前缀，不创建文件夹对象。

公开发布承诺的主要验证目标是 WebDAV、Amazon S3 和 Cloudflare R2。其他 S3 兼容服务要求支持 SigV4 和 `ListObjectsV2`，属于尽力兼容范围。

## 安全同步流程

### 首次同步

插件没有成功同步基线时，手动同步会弹出首次同步确认：

- `双向合并`：本地独有文件上传，远端独有文件下载；同路径差异文件进入确认。
- `以本地为准`：远端调整为当前本地库内容，远端独有文件会先备份再删除。
- `以远端为准`：本地调整为当前远端内容，本地独有文件会先备份再删除。

自动同步遇到首次同步状态时不会执行写入或删除，请先手动选择策略。

### 同步确认策略

插件默认使用”自动”策略。有成功同步基线后，单边新增、单边修改和普通单边删除会自动传播到另一端；如果一端删除而另一端在上次同步后又修改，仍会进入”处理同步确认”。双方同时修改同一路径时，会优先尝试文本自动合并；大文件、二进制文件或缺少基线导致无法合并时，会按不可合并冲突策略自动处理。

不可合并冲突策略默认为”较新文件覆盖”：本地较新则上传，远端较新则下载；如果两边修改时间相同，则使用本地版本。覆盖前仍会把被覆盖的一侧写入 `.remote-sync-trash`。

设置页可切换为”手动”策略，让所有删除和冲突回到确认优先，不可合并冲突也会保留待确认。自动删除还有比例上限；如果单次同步待自动删除数量超过当前文件总数的设定比例，会降级为待确认，避免远端列表异常导致大批量误删。旧版本保存的”安全”或”平衡”策略配置会自动迁移为”自动”。

### 备份恢复

插件在覆盖或删除前会把原文件写入当前设备 Vault 的 `.remote-sync-trash/<批次>/<来源>/原路径`。本地文件被覆盖或删除时来源为 `local`；远端文件被覆盖或删除时，插件会先读取远端原文件并写入当前设备本地备份，来源为 `remote`。

`.remote-sync-trash` 是本地恢复区，不会作为普通同步文件参与计划，也不会计入“已跳过”。可通过命令面板执行 `恢复同步备份`，选择备份文件恢复到原路径；如果原路径已有文件，会被所选备份覆盖。

### 失败诊断

同步失败时会显示失败文件、阶段和错误摘要，例如备份本地、备份远端到本地、上传、下载、删除、合并或保存同步状态。失败后已经生成的本地备份会保留，下一次同步会重新尝试主操作。

### 自定义请求头

每行一个请求头：

```text
User-Agent: RemoteSync
X-Trace-Id: example
```

空行会忽略；格式错误会提示具体行号。`Authorization`、`Host`、`Content-Length` 和 `x-amz-*` 由插件管理，不能在自定义请求头中覆盖。其他与协议内置头重名时，以插件内置头为准。
